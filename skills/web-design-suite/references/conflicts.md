# Conflicts: precedence table

Where two source skills disagree, this table is the ruling. Each row names the winning rule and why. Reference files already follow these rulings; this file exists so the merge is explicit and auditable. Cite rows as `conflicts.md C#`.

**Standing rule (C0): the brief beats every row below.** If the user pins a font, palette, era, layout, motion level or style (including one listed as a tell), do it, and do it well.

Source keys: TS taste-skill, RD redesign-skill, SO soft-skill, MN minimalist-skill, BR brutalist-skill, GPT gpt-tasteskill, ST stitch-skill, IM impeccable, EM Emil Kowalski skills, MIFB make-interfaces-feel-better, TD transitions.dev, GS GSAP skills, VC Vercel skills and guidelines, CD Chrome DevTools skills, FD frontend-design (Anthropic), HZ hzblj-skills, AS audit-suite.

## Layout and composition

| # | Conflict | Winning rule | Why |
|---|---|---|---|
| C1 | Eyebrow labels: TS allows 1 per 3 sections; SO wants a pill eyebrow over every H1/H2; IM bans them outright; FD says avoid. | No eyebrow/kicker by default. At most one on the page, and only when it carries information the heading cannot (date, status, category the reader needs). | Three of four sources reject the pattern; the single allowance keeps TS's escape hatch for real information. |
| C2 | Hero alignment: TS and ST ban centered heroes at high variance; GPT prefers a centered cinematic hero; IM says split-hero and centered-headline-over-cards are both the template. | Neither split nor centered is a default. Pick the composition from what the hero must show; centered is fine for manifesto, launch and editorial briefs. Every hero carries a real visual, demo or type treatment, never text plus a blob. | IM shows both shapes are templates; TS already carves out the centered exception. |
| C3 | Cards: SO wants "double-bezel" nested shells; IM bans nested cards; image-to-code bans box-in-box; TS: cards only when elevation means hierarchy. | No nested containers, including double-bezel shells. Use a card only when elevation encodes hierarchy or the item is an independent, actionable object. | Three sources against one. |
| C4 | Radius: TS wants one radius system; RD says vary radius; MIFB requires concentric radii; FD flags one radius on everything. | One documented radius scale tied to hierarchy, nested radii concentric (outer = inner + padding). | Not truly opposed: a scale plus concentric math satisfies all four. |
| C5 | Section spacing: GPT `py-32..48` everywhere; SO `py-24..40`; IM flags monotonous spacing. | Spacing comes from the density dial with deliberate rhythm: tight inside groups, generous between, more above a heading than below. Never one giant value repeated. | IM's rhythm rule is measurable; fixed giant padding is itself a tell. |
| C6 | CTA count: ST one primary and no secondary; TS one primary plus at most one secondary; GPT exactly two. | One primary, at most one secondary, with different intents. Never two CTAs with the same intent on the page. | TS's version is the middle and adds the duplicate-intent check. |
| C7 | Nav: SO bans edge-to-edge sticky bars and wants a floating pill; TS caps height and requires one line. | Nav form follows the visual world. Hard limits: one line at desktop, 64 to 72px tall by default, sticky only on long pages. A floating pill is not a default. | SO's ban is taste, TS's limits are measurable. |
| C8 | FAQ: RD calls accordions generic; MN uses them; IM accepts disclosure. | Show answers inline when there are six or fewer; use an accordion beyond that. | Combines RD's point with IM's progressive disclosure. |

## Typography

| # | Conflict | Winning rule | Why |
|---|---|---|---|
| C9 | Serif display: TS strongly discourages it and bans Fraunces/Instrument Serif; ST recommends exactly those; MN and RD pair serif headings with sans body. | No reflex serif. Use a serif only when the brand names one or the subject's world genuinely uses it and you can say why. Never default to Fraunces, Instrument Serif, Playfair, Newsreader, Cormorant or an oversized italic serif hero. | TS, IM and FD all identify the italic serif hero as a top AI tell. |
| C10 | Font shortlists: TS recommends Geist, Satoshi, Outfit, Cabinet Grotesk; IM lists Geist, Outfit, Inter, DM Sans, Plus Jakarta, Space Grotesk as overused; EM/Apple default to the system font. | Decide by mode. Operate and Read surfaces: system stack or one workhorse UI face (Inter or Geist are fine). Persuade and Experience: choose a face for the subject; picking from either source's shortlist requires a written reason. | Any shortlist becomes the new default once reused; mode is what changes the right answer. |
| C11 | Single-word emphasis: TS says italic/bold of the same family is the right move; FD lists accenting one word as a top tell. | No single-word accent (italic, weight or color) by default. Use it only when the brand voice does it. | FD's calibration is newer and matches IM's italic-display warning. |
| C12 | Heading case: VC web guidelines say Title Case; VC writing guidelines, RD, HZ unslop and FD say sentence case. | Sentence case for headings, buttons and labels. In redesigns keep the incumbent convention. | Four sources against one; VC contradicts itself and its newer guide picks sentence case. |
| C13 | Quotes: VC, TS and EM require curly quotes; HZ unslop says straight quotes. | Curly quotes and `…` in rendered UI copy; straight quotes in code and developer prose. | Unslop targets PR and doc prose, not rendered typography. |
| C14 | Em dash: TS, VC writing and HZ ban it entirely; IM only flags saturation. | Zero em or en dashes as punctuation in UI copy. Ranges use a hyphen. Code, quotations and legal text are exempt. | Three sources ban it; cheap to enforce mechanically (`anti-slop.md`). |
| C15 | Mono labels: BR and TS use mono metadata strips; FD and IM call mono-as-costume a tell. | Monospace only for code, data, measurements and keyboard keys. | The brutalist world can still use it when the brief picks that world (C0). |

## Color and surface

| # | Conflict | Winning rule | Why |
|---|---|---|---|
| C16 | Accent budget: TS one accent, saturation under 80%; IM allows Committed or Drenched color strategies. | Pick a color strategy first (`color/color-system.md`). Restrained means one accent under TS's cap; Committed, Full and Drenched are allowed on Persuade and Experience surfaces when the brief permits. | TS's cap is a good Restrained rule but would forbid whole legitimate worlds. |
| C17 | Near-black: TS, RD, ST ban `#000` and suggest `#0a0a0a`/`#111`; FD lists tinted near-black `#0B0B0B`/`#111` as a tell. | Derive ink and grounds from the palette's own hue (low-chroma OKLCH). Neither pure `#000` nor the generic `#0a0a0a`/`#111` reflex. | Satisfies both: no pure black, no reflex replacement. |
| C18 | Warm cream grounds: MN and SO use warm off-white/cream; TS bans the beige-brass palette; IM and FD flag cream as the AI default. | No cream or beige ground by reflex. Use it only when the brand or subject requires it and you can say why. | Three sources against two style presets. |
| C19 | Dark mode: TS requires both modes on consumer pages; IM says choose light or dark from the use scene and never invert mechanically. | Persuade/Experience: one committed theme chosen from the physical use scene, with `color-scheme` and `theme-color` set. Operate/Read: ship both themes via semantic tokens. | A committed marketing world rarely survives inversion; tools are used in all lighting. |
| C20 | Dark mode implementation: TS allows per-element `dark:` pairs; HZ says flip tokens once. | Semantic tokens remapped in one place; `dark:` only for genuine one-offs. | One switch point, fewer misses. |
| C21 | Texture: RD and GPT add grain, mesh gradients and radial blurs to avoid flatness; IM's detector bans radial halos, spotlight glows and grid-line backgrounds; FD flags gradient washes. | Flat surfaces are fine. No decorative glows, mesh blobs or grid-line backgrounds. Grain only when the world's material is print or film, on a fixed `pointer-events: none` layer. | IM's rules are deterministic and the patterns are the most recognisable tells. |
| C22 | Glass: TS and SO use glassmorphism as a premium move; Apple uses translucency for floating chrome; IM refuses glass as decoration. | Translucency only for floating chrome over moving content (nav, toolbar, sheet), with a `prefers-reduced-transparency` solid fallback. Never on cards. | Apple's material rule gives the purpose IM demands. |
| C23 | Shadows: SO wants wide diffuse shadows; MIFB uses a 1px ring plus small layered shadows; IM flags a hairline border plus wide shadow on every card in a row. | Elevation via MIFB's ring-shadow tokens or one defined edge. Never hairline border plus wide diffuse shadow repeated across a row. | Reconciles MIFB's technique with IM's detector. |

## Motion

| # | Conflict | Winning rule | Why |
|---|---|---|---|
| C24 | Scroll animation on marketing pages: AS (Emil, marketing) bans scroll fade-ups and non-1:1 parallax; SO wants every element to enter on scroll; TS and GPT use GSAP pins and horizontal hijacks; IM wants one authored moment. | No per-section fade-up reveals. One authored focal moment per page. Scroll-scrubbed or pinned sequences only when the content is a real sequence and MOTION is 7 or higher, mapped 1:1 to scroll. Never change scroll speed or direction. | Majority (AS, IM, FD, EM) against reveal-everything; TS's pin skeletons survive for genuine sequences. |
| C25 | Smooth-scroll inertia: RD recommends it; AS bans scroll hijacking. | No inertia or smooth-scroll libraries by default. `scroll-behavior: smooth` for anchor jumps only, off under reduced motion. | Native scroll physics, accessibility and performance. |
| C26 | Reduced motion: AS says disable everything including opacity; GS example sets duration 0; EM, IM, Apple, MIFB say gentler, not zero. | Remove spatial movement, parallax, loops and autoplay; keep short opacity and color transitions that communicate state. | Vestibular triggers are movement, not fades; feedback must survive. Four sources against two. |
| C27 | Animatable properties: TS, EM, MIFB, VC say transform and opacity only; IM adds blur, clip-path, mask, filter; EM's own recipes use clip-path and blur. | Default to transform and opacity. clip-path, mask and blur (8px or less in motion, never above 20px) are allowed on small, isolated elements when verified smooth. Never width, height, top, left or margin (accordion height is the one exception). | The union of what the sources actually ship. |
| C28 | Easing tokens: TS/IM `(0.16,1,0.3,1)`, EM `(0.23,1,0.32,1)`, TD `(0.22,1,0.36,1)`, MIFB `(0.2,0,0,1)`. | One set: `--ease-out: cubic-bezier(0.23,1,0.32,1)`, `--ease-in-out: cubic-bezier(0.77,0,0.175,1)`, `--ease-drawer: cubic-bezier(0.32,0.72,0,1)`. Reuse the project's tokens if they exist. | The strong ease-outs are perceptually near-identical; one token set beats four. EM documents the fullest decision table. |
| C29 | Durations: EM keeps UI under 300ms; SO wants 800ms+ entrances; IM allows 500 to 800ms focal entrances. | Product UI follows the table in `motion/principles.md` (all under 300ms except modals/drawers to 500ms). One authored marketing focal sequence may run 500 to 800ms. Nothing else exceeds 400ms. | EM for UI, IM for the single authored moment. |
| C30 | Press scale: MIFB always 0.96; EM 0.97; TS 0.98. | `scale(0.97)` default; never below 0.95. | Midpoint of three sources; the 0.95 floor is shared. |
| C31 | Springs: TS stiffness 100, damping 20; EM bounce 0.2; Apple and MIFB bounce 0. | Default `{ type: "spring", duration: 0.4, bounce: 0 }`. Bounce 0.1 to 0.2 only after a gesture that carried momentum (flick, throw, drag release). | Apple's rule explains when overshoot reads as physical. |
| C32 | Bounce/elastic curves: IM bans them; TD uses overshoot on badges, toggles and hover-out; EM allows bounce for playful UI. | No bounce or elastic easing curves. Overshoot only via a momentum spring (C31) or an explicitly playful brief. | IM's detector rule plus EM's own "avoid bounce in most UI". |
| C33 | Stagger: EM 30 to 80ms; MIFB ~100ms; TD 40ms with total under 300ms. | 40 to 80ms per item, total stagger at most 400ms, only for one-off entrances. Never block interaction. | Overlap of all three. |
| C34 | Ambient loops: ST puts a perpetual loop on every active component; TS only when meaningful; IM flags pulsing dots; FD says sparingly. | No perpetual loops by default. Loops only for genuinely live state; they stop offscreen and under reduced motion. | Three against one. |
| C35 | Marquee: TS allows one per page; IM flags any auto-scrolling marquee; AS bans auto-advancing carousels. | No auto-scrolling marquee or carousel by default. If the brief demands one: one only, pausable, stops offscreen and under reduced motion. | Stricter rule wins when two sources agree. |
| C36 | Tool choice: TS defaults to Motion; GS recommends GSAP as default; EM and HZ say cheapest tool first. | Ladder: CSS transition, then `@starting-style`, then WAAPI, then Motion (React, needing springs, layout, exit or gestures), then GSAP (timelines, scroll scrub/pin, SVG, SplitText). Never Motion and GSAP in the same component tree. | Cheapest-first avoids dependencies; TS's "never mix" rule kept. |
| C37 | GSAP in React: TS skeletons use `useEffect` + `gsap.context`; GS official guidance prefers `useGSAP`. | `useGSAP()` with `scope`; `gsap.context()` + `revert()` only where `@gsap/react` is unavailable. | Official vendor guidance. |
| C38 | Motion `x`/`y` shorthands: TS uses them; EM says they drop frames under load. | Use the full `transform` string for motion that runs while the page is busy (load, route change); shorthands are fine for idle micro-interactions. | EM's caveat is measured; GSAP's own `x`/`y` aliases are unaffected. |
| C39 | `will-change`: GS says set it on animating elements; MIFB and IM say only on observed first-frame stutter. | Only on observed stutter, only for transform, opacity or filter, removed after. | Two against one; layers cost memory. |

| # | Conflict | Winning rule | Why |

| C40 | Full-height hero: TS `min-h-[100dvh]`; EM `100svh` for heroes and `100dvh` for app shells. | `min-height: 100svh` for heroes and first screens, `100dvh` for app shells and bottom-pinned UI. | `dvh` resizes as the URL bar moves and shifts marketing layout; `svh` is stable. |

| C43 | Destructive actions: VC wants a confirmation modal or undo; IM and Apple prefer undo. | Undo when the action is recoverable; a confirmation that names the action and object only when it is irreversible. | Confirmation overuse trains click-through. |

| C46 | Images: TS says image tool first, then picsum seeds; RD/MN place low-opacity background photos; IM bans buried rasters and requires verified imagery. | Real imagery at real visibility: generated, provided or verified stock. ## Referenced but not merged

- **transitions.dev**: its licence forbids redistributing the transitions library, so its 35 transitions and motion-token tables are not copied. Install it separately for drop-in transitions; where its token values disagree with C28 to C33, this plugin's tokens win inside projects that do not already use transitions.dev tokens.
- **Impeccable engine**: the detector and live mode need the Impeccable binary. They are optional; see README.
